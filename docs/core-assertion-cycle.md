# Assertion observations and bounded syntax reuse

`result_assertion` is now independent of `obligation_evidence`. It records a located baseline assertion on a resolved function result, with its call/value path and consumer constraints. It does not prove an input reaches the changed operation, observed execution, or detection of a specific regression. Existing behavioral ranks are retained; an observation without a supported changed-operation obligation stays outside the behavioral-evidence category. The summary displays that distinction, and the verification gap names the missing changed-operation link instead of incorrectly saying no result assertion exists.

Known `pytest.mark.parametrize` test bodies can be inspected when the module import is unshadowed and marker metadata is bounded literal data. Tuple argument names and bounded literal string concatenation/repetition are supported without executing decorators or fixtures. Dynamic metadata, indirect fixtures, shadowed marker bindings, class decorators and arbitrary wrappers remain unresolved. These extra observers have a separate 512-test/2,048-node budget; they do not displace the existing 1,024-function summary universe. Observer truncation remains explicit.

Opaque calls that receive callable/module bindings stop subsequent alias reasoning. Short-circuit expressions stay outside the value-flow subset, and branch-dependent result joins explicitly report uncertainty. Reassignment, unrelated literal fields, broad class references and unresolved descriptor/dynamic dispatch cannot establish a new result observation.

Profiling showed repeated `_bindings` and `_dynamic_namespace` AST traversals and repeated uncertainty-list scans dominated avoidable flow cost. Immutable lexical facts are reused only within a request, keyed by the already-parsed AST object. Each scan copies its local binding set before mutation. Before/after dependency-sensitive symbol tables and summaries are still recomputed, and every new CLI/MCP request rereads, reparses and rechecks source, dependency inventories, configuration and analyzer version. There is no persistent parsed-source or summary cache. A hash set and one limit flag preserve the original uncertainty order/cap record without repeated linear scans.

The old unclosed-quote case remains unsupported at the changed loop-exit level. Its two baseline assertions are exposed as function-result observations, with no fabricated loop obligation or claim of changed-site coverage. Empty inputs return before the loop; their assertion is a baseline API result check. The original strict obligation score is preserved separately from the new observation measure.

Cycle receipts and source-labeled fresh cases are in the sibling `core-assertion-evaluation-2026-10-12` directory. They are static-source judgments by the same assistant, not independent validation. No external repository tests or generated drafts were executed, and no graph provider or public tool schema was replaced.
